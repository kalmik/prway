Guided review

One chunk at a time,
in the order that makes sense.

PRway reads the PR first and gives you a reading order: the core change, then what depends on it. You go chunk by chunk and approve as you go. Only you see the approvals, and new commits don't reset them.

A plan before you start

What the PR is for, which files carry the change, and what's not explained by the description.

Only what matters

An AI review reads the whole PR and decides chunk by chunk what you need to read. Docs, tests that follow the code, renames and wiring are pre-approved, and you can spot-check them any time.

A review that shows its work

Up to five findings, each at a line, with the callers, schemas and tests the AI read to confirm it. No style nits, and no findings is a fine answer.

Teach it what's noise

Mark a hint 👎 and say why. Later notes skip that kind of point and follow your reason as a rule, so the AI gets less picky over time.

A real code view

Every PR is checked out locally. Go to definition, find references and open any file at the PR's head, like in your IDE.

Ask about any line

Click a line number and ask in chat. The chat can read the rest of the repository, so it looks up callers and tests itself.

Background

Know how it worked
before the PR.

Most tools summarize the diff. PRway traces the core of the change through the code, back to the controllers and jobs that reach it, and explains the old behaviour and the business rules the PR changes, with links to the code and to the earlier PRs that shaped it.

  • Cached, not re-read. Traces and function summaries are kept and reused, so the next PR on the same code is fast.
  • Editable. Fix a function summary once and your version wins from then on.
  • It sharpens the review. Chunks outside the core change can be pre-approved, so the guided view only shows what matters.
Late fee per period · before this PR

A late fee was charged when the invoice worker saw an unpaid invoice with notified_at set, and the worker cleared that flag after charging. invoice_worker.ex:88

Retries after a crash could charge twice, which is why #311 added the 24h guard in the scheduler.

What changes

The rule moves into LateFees.apply/2 and keys on the billing period instead of the flag.

Watch out

Backfill reuses apply/2 with now in the past: periods are computed from it, so old invoices get their own period.

How it works

From "review requested" to submitted.

Read the plan

The summary says what the PR does and what changed in the rules. The guide gives the reading order; the background, the history.

Submit to GitHub

Your comments go out as one review: approve, request changes or comment. Threads and replies stay in sync.

Privacy

Runs on your machine.

There's no PRway server. Your code is cloned to your computer, and only the PR's material goes to the AI account you chose.

  • Tokens in your keychain. The GitHub token and API keys are stored with the operating system's encryption, never in plain files.
  • Read-only AI. When the chat reads code, it can only read the PR's checkout, nothing else on your disk.
  • Plain folders. Clones and worktrees live in ~/.prway, so you can open any PR in your editor.
